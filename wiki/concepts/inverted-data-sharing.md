# Inverted Data Sharing

## Summary

Inverted data sharing is the cloud-era pattern in which users come to data stored in central cloud locations to perform analysis, rather than downloading the data to store and analyze locally — a sea change from the dbGaP-era model of distributed local copies [[sources/web-2023-04-12-931]]. Dahlquist, Nelson, and Fullerton (2023) identify this inversion as one of two key differences between the new NIH cloud-based biomedical data commons and pre-existing data sharing mechanisms [[sources/web-2023-04-12-931]].

## Key claims

- Cloud-based platforms 'invert' data sharing in that users come to data stored in central cloud locations for analysis, rather than downloading data to store and analyze locally [[sources/web-2023-04-12-931]].
- The second key difference flagged alongside inversion is the development of streamlined mechanisms for both user authentication and authorization for use of data stored on cloud platforms [[sources/web-2023-04-12-931]].
- Cloud-based platforms represent a partial continuation of prior genomic data sharing practices but also a sea change for data stewards in the novel ways users can find, access, and analyze data [[sources/web-2023-04-12-931]].
- AoURH operationalizes the inversion by permitting analysis of registered and/or controlled data only on the platform, prohibiting screenshots and downloads of participant-level data [[sources/web-2023-04-12-931]].
- BDC operationalizes the inversion by making participant-level controlled-access data non-downloadable [[sources/web-2023-04-12-931]].
