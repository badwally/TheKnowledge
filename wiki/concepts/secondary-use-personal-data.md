# Secondary Use of Personal Data

## Summary

Secondary use of personal data refers to using data that was originally collected for one purpose (typically a service the data subject was using) for a different, downstream purpose such as research, product development, or third-party analytics [[sources/web-2021-05-05-125]]. Data cooperatives reframe secondary use as a member-governed transaction: queriers pay to run vetted algorithms against pooled member data, and members can revoke access at any time, holding the cooperative responsible for keeping data inside the cooperative's control [[sources/web-2024-04-04-ad6]].

## Key claims

- The MIT Open Algorithms (OPAL) approach addresses the revocability problem by requiring queriers to submit algorithms and queries to the cooperative to be run, preventing queriers from taking, owning, or linking cooperative data with external data sources [[sources/web-2024-04-04-ad6]].
- Consent systems must intersect with regulatory frameworks including GDPR (EU, general) and HIPAA (US, healthcare), and querier algorithms must be vetted for member safety, consent, and bias [[sources/web-2024-04-04-ad6]].
- Health data cooperatives in particular may reduce barriers to data sharing for doctors and researchers and increase members' understanding of where and how their data is used — though these benefits are not yet empirically verified [[sources/web-2024-04-04-ad6]].
- Data altruism — consensual contribution of personal data to causes like pharmaceutical research — is a recognised motivation for participating in secondary use through cooperatives [[sources/web-2024-04-04-ad6]].
