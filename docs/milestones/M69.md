### INT-1 — Gmail newsletter poller

- `src/gateway/pollers/gmail_newsletters.py` (new): `GmailNewsletterPoller` (name: `gmail-newsletters`, source_type: `web`).
  - Auth: `GMAIL_ADDRESS` + `GMAIL_APP_PASSWORD` env vars (App Password; requires Gmail 2FA).
  - IMAP4_SSL to `imap.gmail.com:993` via stdlib `imaplib`.
  - Sender config: `.knowledge/pollers/gmail-newsletters/config.yaml` → `senders: [{address, domain}]`; optional `label` (default INBOX) and `max_messages` (default 50).
  - If `senders:` is configured, only accepts messages from listed addresses (sender gate).
  - Cursor: `.knowledge/pollers/gmail-newsletters/cursor.yaml` → `last_uid: <int>`. Advances the highest UID after each run.
  - Writes to `raw/web/web-<YYYY-MM-DD>-<sha3hex>.md` with frontmatter `meta.source_app: gmail-newsletter`, `meta.sender`, `meta.message_id`, `meta.imap_uid`.
  - Idempotent: skips slugs whose file already exists.
  - `_decode_header()`, `_extract_text()` handle RFC-2047 encoded headers and multipart bodies (plain-text preferred over HTML).
  - Registered as `gmail-newsletters` in `pollers/__init__.py`.
  - 14 tests in `test_int1_gmail_newsletters.py`.

### INT-2 — RSS/Atom feed poller

- `src/gateway/pollers/rss.py` (new): `RSSPoller` (name: `rss`, source_type: `web`).
  - No `feedparser` dep — uses stdlib `urllib.request` + `xml.etree.ElementTree`.
  - Supports RSS 2.0 and Atom 1.0.
  - Feed config: `.knowledge/pollers/rss/feeds.yaml` → `feeds: [{name, url, domain}]`; multiple feeds in one run.
  - Cursor: `.knowledge/pollers/rss/cursor.yaml` → per-feed `{last_guid, last_pubdate}`; skips items already seen or older than last run.
  - Writes to `raw/web/` with `meta.source_app: rss`, `meta.feed_name`, `meta.feed_url`, `meta.guid`.
  - Idempotent: skips slugs whose file already exists; slug derived from item URL + publish date.
  - Handles per-feed fetch errors gracefully (continues to next feed, reports in `errors`).
  - Registered as `rss` in `pollers/__init__.py`.
  - 17 tests in `test_int2_rss_poller.py`.

**Bug fixed during implementation:** Python `xml.etree.ElementTree.Element` evaluates as falsy when it has no children (only text). Using `elem_a or elem_b` for fallback find chains fails silently when `elem_a` has text but no children. All fallback find chains use explicit `is None` checks.

## Design notes

- Gmail poller uses IMAP rather than the Gmail MCP tools. MCP tools are only callable in Claude sessions; gateway Python code must use direct API/protocol access. `imaplib.IMAP4_SSL` is stdlib and zero-dep.
- RSS poller skips feedparser (not in venv) in favor of stdlib. The parsing handles RSS 2.0 and Atom 1.0 — the two dominant feed formats. Edge cases (RSS 1.0/RDF) fall through to empty list rather than crashing.
- Both pollers follow the cursor + idempotency + write-through pattern established by `apple_notes.py` and `link_rot.py`.
