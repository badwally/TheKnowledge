# M50 — QUAL-12 evaluation framework

**Date:** 2026-05-24
**Tag:** `m50-qual12-evaluation-framework`
**Phases:** A (`0133fb8`) · B (`999f104`) · C (`e37ba48`) · D (`aa332f0`) · E (`2511a1c`) · F (`02a280f`) · G (`5b33ec3`) · H1 (`a5db183`) · H2 (live hand-test) · I (this file + WIKI/BUILD updates) · plus parser fix `24aae19` from the hand-test feedback loop

Per-domain evaluation substrate so future milestones can prove (or disprove) "the system got better." v1 lands the schema, runner, LLM-as-judge, persistence, CLI/MCP surface, `wiki status` integration, and a 15-Q/A hand-drafted seed set for `glp1-reward-modulation`. Subsequent milestones add CI hook, more domains, retraining loop, mode-A (re-run-`wiki query`) variant, judge prompt tuning, trend visualization.

## Goal

Every prior milestone shipped on intuition. The review (CC4) named this as the largest single-cause gap: filter calibration used n=5 samples (statistically meaningless), no regression detection, no signal that a wiki change improved or hurt anything. QUAL-12's role is to make "did the system get better between M49 and M50?" a question with a numeric answer.

Mode B (wiki-state-only) was chosen over mode A (re-run `wiki query` synthesis): mode B exercises the surface downstream consumers (chief-of-staff, ai-tutor, newbiz) actually hit, doesn't write new draft pages on every eval run, is faster, and isolates the eval framework from synthesis-pipeline variance. Mode A is deferred to M50.x when needed.

Hybrid scoring was chosen over pure source-id-strict or pure semantic. `must_cite` stays source-id-strict (the wiki's cite-grounding discipline is the load-bearing invariant). `must_assert` / `must_not_assert` use LLM-judged semantic match (so the judge accepts paraphrase but catches the wrong claim).

## Components shipped

**Phase A — schema (`0133fb8`).** `gateway.evaluate.schema`: `Golden`, `EvalResult`, `EvalRunSummary` dataclasses. `load_goldens` / `save_goldens` with duplicate-id + required-field + numeric-rubric-weight validation. `scaffold_template` for new-domain bootstrap (refuses to overwrite). `evaluate_judge` stage registered in `gateway.llm.config` defaulting to Sonnet 4.6. 5 schema tests + 1 config test.

**Phase B — wiki context (`999f104`).** `gateway.evaluate.wiki_context.load_wiki_context(domain, max_chars=500_000) -> str`. Assembles all synthesis pages (full body), concept pages (head 20 lines), entity pages (head 15 lines), and the raw bodies of every source referenced via `synthesizes:`. XML-wrapped per block to harden against prompt injection (same convention M49 cite_suggest established). `sources/` prefix stripped when resolving raw files (same M49 lesson). `ContextTooLargeError` if the assembled string exceeds the budget. 6 tests.

**Phase C — Judge (`e37ba48`).** `gateway.evaluate.judge.Judge` wraps `AnthropicAPIClient` (one instance per evaluation run so the cache-control-marked system prompt accrues benefit across questions within the 5-min TTL). System prompt embeds the rubric + JSON envelope spec. User prompt = WIKI CONTEXT + QUESTION + GOLDEN EXPECTATIONS. Sonnet 4.6 emits structured JSON; the parser handles code-fence wrapping, prose preamble, and trailing content (this last one came from the hand-test — see § Parser fix). 6 judge tests + 2 deferred-from-Group-1 schema tests for `rubric_weight` numeric-type validation and weight-sum warning.

**Phase D — persistence (`aa332f0`).** `gateway.evaluate.persistence`. `write_run(summary)` writes `.knowledge/eval/<domain>/runs/<UTC-ts>.yaml` with the full `EvalRunSummary` serialized. `append_to_trend(summary)` appends one row to `.knowledge/eval/<domain>/trend.csv` (creates header on first call). `read_trend(domain)` returns the rows as dicts. Helpers: `eval_dir_for`, `runs_dir_for`, `trend_path_for`, `goldens_path_for`. 5 tests.

**Phase E — runner (`2511a1c`).** `gateway.evaluate.runner.run_evaluate(domain, *, limit=None, client=None) -> EvalRunSummary`. Flow: load goldens (or `NoGoldensError`), slice by limit, load wiki context once, instantiate Judge once, score each golden, compute mean, persist + append trend. 5 tests verify dispatch count, limit, missing-goldens-raises, persistence wiring, Judge-instantiated-once.

**Phase F — gateway op + CLI + MCP (`02a280f`).** `gateway.ops.evaluate_op.evaluate_op(*, domain, limit, scaffold)` covering scaffold path / missing-domain error / runs-with-mean. `wiki evaluate` CLI subcommand with positional `domain` (optional), `--limit`, `--scaffold`. MCP parity tool `wiki_evaluate`. 5 op tests + parity test green.

**Phase G — `wiki status` integration (`5b33ec3`).** New "Evaluation scores (last run per domain)" block reads `.knowledge/eval/*/trend.csv` and shows mean_score + delta vs prior run per domain (or "initial" for first runs). 6 tests cover multi-domain, empty state, negative delta, alphabetical sort, no-trend-rows-skipped.

**Phase H1 — seed goldens (`a5db183`).** Hand-drafted 15 Q/A pairs for `glp1-reward-modulation` covering: mesolimbic dopamine mechanism (q01), compound comparison (q02), microdosing PK (q03), GLP-1-induced anhedonia + bupropion countermeasure (q04), suicidality surveillance (q05), alcohol SUD evidence (q06), Penn State opioid craving (q07), nicotine reward (q08), SELECT cardiovascular trial (q09), Alzheimer's brain volume (q10), brain organoid amyloid/tau (q11), 600K veterans observational (q12), body composition / muscle preservation (q13), FSCV dopamine measurement (q14), fMRI food-cue reactivity (q15). Schema fix bundled (commit message documents `load_goldens` rubric_weight default-bypass bug).

**Phase H2 — live hand-test.** First run results recorded in § Hand-test below.

**Phase I — docs + tag (this commit).** WIKI.md ops table + BUILD.md § 10 + this milestone doc + tag.

Three findings from the run:

1. **Parser bug (q09, q14 → 0.00).** Sonnet emitted valid JSON envelope followed by a closing-commentary paragraph. Strict `json.loads` rejected with "Extra data: line N column M". Fix landed in `24aae19`: use `JSONDecoder.raw_decode` (returns the parse-end position) and skip prose preamble before the first `{`. Two regression tests added. A re-run would lift q09 and q14 above zero; not re-running now to conserve API budget.

2. **Cache hit rate: 0%.** The judge system prompt is ~500 tokens, below Anthropic's 1024-token minimum threshold for cache eligibility on Sonnet. Result: every call paid full input cost. The wiki_context block (~23k tokens per call, identical across all 15 calls in a run) is the high-leverage caching target the architecture missed. **M50.1 follow-up:** apply `cache_control` to the wiki_context block, not just the system prompt. Estimated impact: 348k input tokens → ~30k+ (single creation + 14 reads at ~90% discount). Cost drops from $1.16/run to ~$0.15-0.30/run.

3. **`must_cite=[]` ceiling.** 10 of 15 goldens were drafted with empty `must_cite` because I wasn't certain of the source-ids. Mathematically those questions are capped at ~0.55-0.65 (the cite-component contributes 0 × 0.4 = 0). Refining the goldens to populate `must_cite` is the highest-leverage way to lift scores meaningfully; this is the user's editorial work and a natural next step.

## Open follow-ups

- **M50.1: `cache_control` on the wiki_context block.** Highest-impact change (estimated 4-5× cost reduction per run). Small code change in `Judge._build_user_prompt` / `AnthropicAPIClient.call_with_usage` — promote the wiki_context to its own message-block list with `cache_control={"type": "ephemeral"}`.
- **`must_cite` population in the seed goldens.** User-driven; spot-check each q against the wiki and add the source-ids that a correct answer must cite.
- **Mode A (`--mode=query`) variant.** Re-run `wiki query` against each Q/A. Exercises the synthesis pipeline end-to-end. Cost-bearing; deferred until mode B has been used enough to be trusted.
- **CI hook.** Run `wiki evaluate <domain>` on every push for domains with goldens. Compare against prior trend.csv row; PR comment on regression. Requires CI infra not yet present.
- **Per-domain coverage growth.** Author goldens for `condo-capital-infra`, `ai-native-business`, etc. Each domain is independent so this is sequenceable.
- **`wiki query` re-run mode for synthesis-pipeline regression** (the mode A above). Hand-authored deferred until v1 stabilizes.
- **Schema refinement: `validate_rubric_weights` should ignore the empty-defaults case** (a Golden with no `rubric_weight` set in YAML now correctly inherits the dataclass default, but if a user sets `rubric_weight: {}` explicitly they'll get a 0.0-sum warning. Minor.)
