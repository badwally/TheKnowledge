# M52 — Phase 1 Round A (ARCH-2, ARCH-4, ARCH-6, QUAL-4, QUAL-5)

**Date:** 2026-05-25
**Tag:** `m52-phase1-round-a`
**Branch:** `phase1-round-a` → merged to `main`

Five independent hardening items across source immutability, concurrent write safety, pipeline idempotency, lint coverage, and operator visibility. All test-first. No new external dependencies.

## Goal

Tighten the gateway's structural guarantees before the token-efficiency (Round B) and multi-model (Round C) phases land on top of it. The five items address concrete failure modes identified in M49–M51 hand-tests and planning:

- ARCH-2: sources mutated outside the allowlist were undetected; `validate_source_frontmatter_diff` closes the gap.
- ARCH-4: `_materialize` had no per-source file lock and dropped filter scores on disk; concurrent ingest could corrupt source frontmatter.
- ARCH-6: re-running ops on partial state could create duplicate registry sessions or leave lint gaps unreported.
- QUAL-4: broken wikilinks were invisible until a consumer failed a lookup; lint now surfaces them on every `wiki lint` run.
- QUAL-5: operator had no insight into example-bank accumulation per domain; `wiki status` now shows readiness and fires a one-shot log entry at 80%.

## Components shipped

**ARCH-2 — source frontmatter immutability guard (`16903b6`).** `gateway.validator` gains `MUTABLE_SOURCE_FIELDS` (`filter`, `nlm_corpus_ids`, `wiki_pages`, `domains`) and `validate_source_frontmatter_diff(old, new) -> ValidationResult`. Three pipeline callers (`cite.py`, `apply_plan.py`, `filter_correct.py`) now snapshot the frontmatter before mutation and bail early with an error if any non-allowlisted field would change. Previously, bugs or copy-paste errors in any of these callers could silently corrupt the canonical frontmatter of an ingested source. +9 tests covering unchanged fields, each allowlisted mutation, rejected mutations, deletion, and multi-violation accumulation.

**ARCH-4 — per-source lock + filter score writeback in `_materialize` (`df8c00c`).** `gateway.research.orchestrator._materialize()` now acquires a `file_lock(f"ingest-{source_id}")` before writing to `raw/` and writes `front["filter"] = {"score": round(score, 3)}` into the source frontmatter at creation time. Previously, concurrent ingest calls for the same source could race on the write; and filter scores computed in the research pipeline were never persisted to disk, meaning `wiki filter` re-scored on every access. +3 tests: filter score in frontmatter, lock acquisition, and concurrent-write no-corruption.

**ARCH-6 — `register_session` force flag + idempotency lint + op contracts (`08d9202`).** `gateway.nlm_registry.register_session()` gains a `force: bool = False` parameter; `force=True` replaces any existing session (promoted or ephemeral) without raising. Two new lint checks in `gateway.lint.idempotency`: `stale-session` (ephemeral research sessions older than 24 h with no matching query plan) and `no-policy` (domain present in the NLM registry without a corresponding policy file). Module docstrings for `ingest.py`, `finalize.py`, `promote_domain.py`, `cite.py`, `apply_plan.py`, and `filter_correct.py` each gain an `Idempotency:` contract line. +3 tests for `register_session` force, +6 idempotency lint tests.

**QUAL-4 — broken-wikilinks lint scope (`bf44f0e`).** `gateway.lint.broken_wikilinks` walks every wiki page via `walk_wiki_pages()`, extracts `[[<dir>/<slug>]]` targets via `citations.find_wikilinks()`, and resolves each against `wiki/<dir>/<slug>.md`. Unresolved plain links → `SEVERITY_ERROR`; unresolved aliased links (`[[target|alias]]`) → `SEVERITY_WARNING` (forward-reference intent). `nlm:` links are exempt. Findings are deduplicated per `(page, target)` pair so multi-occurrence broken links produce one finding, not N. Registered as `"broken-wikilinks"` in `KNOWN_CHECKS`. +8 tests covering clean state, valid source/entity links, missing source/entity (error), aliased missing link (warning), nlm exempt, and KNOWN_CHECKS registration.

**QUAL-5 — per-domain fine-tune readiness in `wiki status` (`1cc59cc`).** `_finetune_readiness_block()` calls `trigger_states_all()` and renders each domain's example-bank count toward the 500-decision threshold as `domain: count/500 (pct%)`. When a domain crosses 80% for the first time, a `finetune-milestone` log entry is appended and the domain is persisted to `.knowledge/finetune_milestones.yaml` so the entry is not re-fired on subsequent `wiki status` calls. The block is inserted before the evaluation scores section. +6 tests: shows readiness line, count not ready, count at 500/500, empty when no policies, 80% log entry fires, 80% not re-fired on second call.
