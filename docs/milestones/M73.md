### ARCH-13 — Query-plan lifecycle (`status`, `stamp_executed`, `stamp_abandoned`, `archive`)

Query plans accumulate in `nlm/query_plans/` with no lifecycle tracking. ARCH-13 adds:

- `status: planned | executed | abandoned` field on `QueryPlan` dataclass; persisted in YAML
- `executed_at: datetime | None` field stamped when plan completes
- `stamp_executed(session_id)` / `stamp_abandoned(session_id)` helpers
- `archive_old_plans(older_than_days=90)` — moves executed plans older than 90 days to `nlm/query_plans/archive/`
- Orchestrator stamps `status: executed` + `executed_at` on successful `--execute` runs
- CLI: `wiki research --abandon <session-id>` and `wiki research --archive`
- Legacy plans (no `status` field) load as `planned` by default

### QUAL-7 — Retraction + revision monitor for academic sources

64 PubMed + 52 arXiv sources now have active monitoring:

- `pollers/pubmed_retractions.py` — `PubmedRetractionPoller`: checks each `raw/pubmed/*.md` source via NCBI eFetch XML API; stamps `retracted: true` + `retracted_at` on confirmed retractions; cursor tracks last-checked per source (RECHECK_DAYS = 30)
- `pollers/arxiv_revisions.py` — `ArxivRevisionPoller`: checks each `raw/arxiv/*.md` source via arXiv Atom API; records baseline version on first check; stamps `arxiv_revised: true` + `arxiv_current_version` when version increases; cursor per-source
- `lint/retracted_citations.py` — `retracted-citations` check: ERROR for any wiki page citing a source with `retracted: true` in raw frontmatter (QUAL-7)
- Both pollers registered in `pollers/__init__.py`; lint check registered in `ops/lint.py`
- `WIKI.md § 3.1` updated with QUAL-7 retraction/revision fields
