# M54 — Phase 1 Round C (TOOL-10, DOC-1, DOC-6)

**Date:** 2026-05-25
**Tag:** `m54-phase1-round-c`
**Branch:** `phase1-round-c` → merged to `main`

Three ergonomics and onboarding items: shell completion, README reading order, and a glossary. Sequenced last in Phase 1 to avoid documentation drifting against in-flight code changes from Rounds A and B.

## Goal

Lower the barrier for new contributors, agents, and users arriving at the repo cold. Round C items address the most common orientation failures: not knowing what command to run, not knowing where to start reading, and not knowing what terms mean.

- TOOL-10: tab completion was absent; operators had to type full subcommand names.
- DOC-1: README opened with architecture, not orientation — a contributor still had to discover CLAUDE.md, WIKI.md, and TUTORIAL.md on their own.
- DOC-6: ~30 terms were used across codebase, commit messages, and docs without a single canonical definition list.

## Components shipped

**TOOL-10 — Shell completion + `--help` examples (`e6683ce`).** `argcomplete>=3.0` added to `pyproject.toml`. `argcomplete.autocomplete(parser)` wired in `main()` before `parse_args()`. Usage examples (`epilog=`) added to eight key subcommands: `ingest`, `filter`, `query`, `research`, `context`, `evaluate`, `status`, `lint`. Each uses `formatter_class=argparse.RawDescriptionHelpFormatter` to preserve newlines. `docs/shell-completion.md` documents `eval "$(register-python-argcomplete wiki)"` setup and troubleshooting. +11 tests in `tests/gateway/test_cli_help.py`: parser returns correct prog, each of eight subcommands has "Examples:" in its help output, argcomplete is importable, `main([])` exits zero.

**DOC-1 — "New here?" reading order in README (`c8e2026`).** Numbered three-track reading list inserted at the top of `README.md` before the Architecture section. Track A (knowledge work): TUTORIAL.md → `wiki --help` → WIKI.md §§ 1–2. Track B (code contribution): CLAUDE.md → WIKI.md → BUILD.md §§ 9–10 → GLOSSARY.md → `pytest -x`. Track C (agents): CLAUDE.md → `wiki status` → `wiki context` → WIKI.md § Gateway operations. Each step names its output ("after this you can…"). No new docs introduced; all references point to existing files.

**DOC-6 — GLOSSARY.md (`c8e2026`).** `GLOSSARY.md` created at repo root. ~30 terms alphabetical. Seed list from review doc `docs/reviews/2026-05-23-knowledge-system-review.md § 2`, extended with terms introduced in M47–M53: `AnthropicAPIClient`, `Golden`, `Judge`, `OperationResult`, `PromptGuardError`, `Scheduler`, `Session state`, `TranscriptionResult`, `Wiki context`. Each entry: one-line definition + pointer to canonical doc section. Cross-linked from README Documentation table.
