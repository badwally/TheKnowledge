# M51 — INT-11 read-side outbound op (`wiki context`)

**Date:** 2026-05-25
**Tag:** `m51-int11-wiki-context`
**Phases:** A (`68484cb`) · B (`96b586a`) · C (`2e0777a`) · C-fixup (`daed11d`) · D (this file + WIKI/BUILD updates)

Read-side outbound op so sibling `~/code/*` projects (chief-of-staff, ai-tutor, newbiz) can fetch a center wiki page plus an N-hop wikilink-resolved neighborhood through the gateway instead of scraping the filesystem. Single resolver, single walker, two renderers (markdown + JSON), one CLI + MCP surface.

## Goal

INT-11 was the last open read-side integration thread. Sibling projects already cite into the wiki by writing `[[sources/<id>]]` references — but the inverse direction (a consumer asking the wiki "give me page X plus its directly-cited neighbors") required either reading the markdown directly (bypassing the gateway and the audit trail) or constructing a custom shell pipeline per consumer. M51 collapses that into one op with three resolver branches, a deterministic walker, two render formats, and `--caller` audit logging.

The op is intentionally read-only and leaf-shaped: it doesn't mutate state, doesn't unblock further milestones, and doesn't depend on any in-flight work. It exists to give sibling projects a stable contract — slug-or-query in, page-plus-neighbors out, audit logged.

## Components shipped

**Phase A — resolver + walker (`68484cb`).** `gateway.ops.context_op` module with `_resolve_query(query) -> Path | None` (three branches: slug like `synthesis/<slug>`, full path like `wiki/<kind>/<slug>.md`, title substring match against frontmatter `title:`) and `_walk(start, depth) -> list[Path]` (BFS from the start page, follows `[[<kind>/<slug>]]` wikilinks found in body text, deduplicates by resolved path, stops at non-`wiki/` targets — `raw/`, `nlm:`, http URLs). +11 tests covering each resolver branch, the walker's depth bound, dedup, and stop-at-`raw/` invariant.

**Phase B — renderers + orchestrator (`96b586a`).** `_render_markdown(root, neighbors)` emits `## <path> — <title>` header per page followed by body. `_render_json(root, neighbors)` emits `{root: {...}, neighbors: [{...}], stats: null}` with `path`, `slug`, `kind`, `title`, `body` fields per page. `context_op(query, *, depth, fmt, caller) -> OperationResult` is the orchestrator: resolves, walks, renders, logs `context: caller='<id>' target=<path> depth=<n> pages=<m>` to `log.md`. +6 tests covering both renderers, the orchestrator's happy path, and the caller-required-in-log assertion.

**Phase C — CLI + MCP wiring (`2e0777a`).** `wiki context <query> --caller <id> [--depth N] [--format markdown|json]` subcommand in `cli.py`. MCP parity tool `wiki_context` with identical surface in `mcp_server.py`. No new tests — the existing parity-existence-check exercises that the MCP tool is registered.

**Phase C fix-up — `--help` strings (`daed11d`).** `--depth` and `--format` had bare argparse defaults; added single-line help text mirroring the conventions used elsewhere in the CLI.

**Phase D — docs + tag (this commit).** WIKI.md ops table row, BUILD.md § 10 M51 section, this milestone doc, tag.

**Observation — flat citation tree.** Depth-2 returned exactly the same set of pages as depth-1 because every depth-1 neighbor is a `sources/web-*` page whose only outbound wikilink is back to its `raw/web/...` immutable counterpart, and the walker correctly stops at `raw/`. Synthesis pages tend to have this shape (one hop out to source summaries, then a hard wall). Concept and entity pages would likely show real depth-2 expansion. Worth re-validating on a non-synthesis center in M51.x if a consumer reports unexpectedly truncated neighborhoods.

## Follow-ups

- **CLI envelope pollution (resolved post-tag in `bde53af`).** `_emit_result`'s `ok: ... touched: <path>` wrapper corrupted `--format json` for `jq` consumers and added noise to markdown piped into LLM context loaders. Fix: `_run_context` now bypasses `_emit_result`, prints `result.summary` directly to stdout, sends errors to stderr, returns 0/1. Verified: `wiki context ... --format json | jq .` parses; markdown output is clean. Specialization local to `_run_context` (six lines) — premature to generalize until a second op needs raw stdout.
- **`_render_*` and `context_op` lack docstrings.** Phase A helpers (`_resolve_query`, `_walk`) have docstrings; the Phase B additions don't. One-line pass in M51.x.
- **`kind` fallback in `_render_json` uses `p.parent.name.rstrip("s")`.** Corrupts `synthesis → synthesi` when frontmatter is missing or unparseable (latent — only fires on the fallback branch). Replace with a static map `{synthesis: synthesis, concepts: concept, entities: entity, sources: source, mocs: moc, proposals: proposal, artifacts: artifact}` in M51.x.
- **Untested edge cases.** `depth < 0` validation, `wiki/<kind>/<slug>` (no `.md` suffix) resolution branch. Both trivial unit tests.
- **Stats field is always null.** The JSON envelope has a `stats` slot that's wired in the schema but always returns `null`. Either populate it (e.g., `{pages: N, depth_reached: N, dedup_collisions: N}`) or remove it. M51.x.
- **Non-synthesis hand-test.** Re-run the depth-1/depth-2 check on a concept page (deeper citation tree expected) to confirm walker expansion behaves correctly when neighbors have outbound `wiki/` links. The synthesis center used here showed depth-1 == depth-2; not a bug, but the hand-test would benefit from confirming the walker actually expands beyond one hop in the wild.
