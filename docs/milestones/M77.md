## Delivered

### QUAL-14 — Source-decay re-ingest policy

Implements the `supersedes`/`superseded_by` linking pattern for revised sources (arXiv v2, edited blog posts).

**New module:** `src/gateway/ops/reingest.py`

- `reingest(source_id, new_input, domain=None)` — ingests the revised source through the standard pipeline, determines the next versioned ID (`<base>-v2`, `-v3`, …), stamps `superseded_by: <new-id>` on the old raw source, stamps `supersedes: [<old-id>]` on the new raw source, returns the list of wiki pages that cite the old source so affected claims can be reviewed.
- `_version_base(source_id)` — parses `-vN` suffix
- `_next_version_id(source_id)` — increments version suffix
- `_affected_wiki_pages(source_id)` — finds wiki pages citing the old source

**Frontmatter additions** (`WIKI.md § 3.1` + `validator.MUTABLE_SOURCE_FIELDS`):
- `superseded_by: "<new-id>"` — set on old source by `reingest`
- `supersedes: ["<old-id>"]` — set on new source by `reingest`
- Also added QUAL-7 fields (`retracted`, `retracted_at`, `arxiv_revised`, `arxiv_current_version`, `arxiv_baseline_version`) to `MUTABLE_SOURCE_FIELDS` (were missing from the allowlist)

**New lint check:** `lint/superseded_citations.py` (`superseded-citations`, WARNING) — finds wiki pages citing sources with `superseded_by:` set. Registered in `ops/lint.py` and `test_lint.py` KNOWN_CHECKS.

**CLI:** `wiki reingest <source_id> <new_input> [--domain D]` — prints affected pages for review.

**MCP:** `wiki_reingest(source_id, new_input, domain=None)` — same operation via MCP.

**Note:** QUAL-8 (semantic citation-claim coherence on affected pages) is deferred — that's an L-effort standalone item. `reingest` returns the affected pages list so the user can review manually.

**`OperationResult` extended:** added `data: dict` field for structured return data (affected pages, old/new IDs). Field is backward-compatible (defaults to `{}`).
