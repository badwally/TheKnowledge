# M49 — AGT-2 draft closer + TOK-1 Anthropic API client

**Date:** 2026-05-24
**Branch:** `m49-agt2-draft-closer` (planned tag)
**Phases:** A (`5fbbd5b`, `29fbf1e`) · B (`648288f`) · C (`a644efd`) · D (`7f92bb0`) · E (`ad35701`)

Two workstreams bundled into one milestone. TOK-1 provides a second LLM
client (direct Anthropic SDK, separate API key, cacheable system prompt)
as the substrate for cost-sensitive agent-driven operations. AGT-2 is the
first operation to run on it: a daily batch draft-closer that deterministically
finalizes Cat A drafts and optionally applies LLM-proposed citations to
clear Cat B drafts before finalizing them.

## Goal

Stale drafts accumulate faster than human `wiki finalize` throughput. AGT-2
closes the backlog automatically: zero-unresolved-claim drafts (Cat A)
finalize on every nightly run; drafts with unresolved claims (Cat B) get
LLM citation proposals, and the unambiguous + evidence-verified subset
applies and finalizes without human involvement. Proposals that are
ambiguous or have no matching evidence string escalate to a human-readable
per-run report at `.knowledge/finalize-batch/<UTC-ts>.md`.

TOK-1 (Phase A) is a prerequisite: `claude -p` subprocess calls don't
support `cache_control`, so a second client using the Anthropic Python SDK
directly is needed to amortize the repeated system-prompt + source-corpus
tokens across cite_suggest calls. The `ANTHROPIC_API_KEY_RESEARCH` key is
governed by a separate $50/month console cap, independent of Max plan billing.

## Components shipped

### Phase A — TOK-1 AnthropicAPIClient (`5fbbd5b`, `29fbf1e`)

- **`src/gateway/llm/api_client.py`** — `AnthropicAPIClient` class using the
  `anthropic` Python SDK. Reads `ANTHROPIC_API_KEY_RESEARCH` (not the main
  `ANTHROPIC_API_KEY`). System prompt carried with `cache_control: ephemeral`
  so repeated calls over the same source corpus amortize prompt-creation tokens.
  - Status-code-gated retry: retries on 429, 500, 503, 504, 529 with
    exponential backoff; passes through all other error codes without retry.
  - Network-error retry: retries on `APITimeoutError` and `APIConnectionError`
    (structurally identical path to status-code retry; distinct branch for
    future divergence).
  - Independent throttle from `ClaudeCLIClient` — the two clients don't share
    concurrency state.
- **`gateway.llm.config`** — `cite_suggest` stage entry defaulting to
  `claude-sonnet-4-6`.
- **`pyproject.toml`** — `anthropic>=0.28` dependency added.
- **7 unit tests** (`tests/gateway/test_api_client.py`): `cache_control`
  payload shape, status-code-gated retry (429 exhaustion + 400 pass-through),
  network-error retry, non-retryable pass-through, environment variable
  isolation.

### Phase B — `wiki finalize-batch` deterministic engine (`648288f`)

- **`src/gateway/ops/finalize_batch.py`** — `finalize_batch(*, domain=None, limit=None, suggest=False, execute=False, client=None) -> FinalizeBatchResult`. Core engine:
  - Collects stale draft pages (age ≥ lint staleness threshold; optional domain filter + limit).
  - For each page: counts `unresolved_claims` from frontmatter to assign Cat A / Cat B.
  - Cat A + `--execute`: calls existing `finalize()` op. Cat A without `--execute`: dry-run record.
  - Cat B + `--suggest` + `--execute`: delegates to `cite_suggest` then applies (Phase D).
  - Writes per-run report to `.knowledge/finalize-batch/<UTC-ts>.md`.
  - Appends a `finalize-batch` log entry per run.
- **CLI `wiki finalize-batch`** subcommand with `--suggest`, `--execute`,
  `--domain`, `--limit` flags.
- **MCP `wiki_finalize_batch`** tool added to `mcp_server.py`. The K2 parity
  test from M47 went red the moment `finalize-batch` landed in
  `cli.IMPLEMENTED` without an MCP wrapper; adding the tool restored green —
  same forcing-function dynamic as M48/K1.

### Phase C — `gateway.ops.cite_suggest` (`a644efd`)

- **`src/gateway/ops/cite_suggest.py`** — `suggest_cites(page_path, *, client=None) -> list[CiteSuggestion]`.
  - Loads the draft page and all sources referenced by `sources:` + `synthesizes:` frontmatter.
  - Assembles an XML-wrapped prompt: `<page>` block + one `<source id="...">` block per source.
  - Calls `AnthropicAPIClient` with the `cite_suggest` stage config (Sonnet 4.6).
  - Parses JSON response: list of `{claim, source_id, evidence_quote, confidence}` objects;
    malformed response items are logged and skipped.
  - Ambiguity detection: if two suggestions target the same claim span, both are escalated
    (not auto-applied) regardless of confidence.
  - Evidence-quote verification: `evidence_quote` must be a literal substring of the source
    body (after NFKC normalization). Suggestions that fail verification are escalated.
  - Returns `CiteSuggestion` dataclasses with `auto_appliable: bool`, `escalation_reason: str | None`.
- **CLI `wiki cite --suggest <page>`** — emits machine-runnable `wiki cite <page> LINE:SID` invocations
  for `auto_appliable=True` suggestions, plus commented escalations. Does not modify the page.

### Phase D — Aggressive integration (`7f92bb0`)

- **`finalize_batch` + `--suggest` + `--execute` path** — for each Cat B draft:
  1. Calls `suggest_cites(page)`.
  2. Applies each `auto_appliable` suggestion via `gateway.ops.cite.cite()`.
  3. If all auto-appliable suggestions applied and `unresolved_claims` drops to 0, calls
     `finalize()`.
  4. Half-mutated escalations (some cites applied, finalize failed or residual unresolved
     claims remain) are explicitly flagged in the run report and log with the list of applied
     vs escalated suggestions — recoverable via `git diff`.
- Per-run report writer at `.knowledge/finalize-batch/<UTC-ts>.md` extended to include
  Cat B suggestion detail (applied count, escalation reasons, finalize outcome).

### Phase E — Daily scheduler entry (`ad35701`)

- **`.knowledge/schedule.yaml`** — `daily-finalize-batch` job at `04:30 UTC`,
  command `wiki finalize-batch --suggest --execute`, enabled.
- Respects K4 scheduler substrate (M48): `cooldown_seconds` guard prevents
  double-execution on launchd restart.

## Follow-ups

- **cite_suggest module split** — if `suggest_cites` gains a `--mode` flag or
  a second LLM pass (e.g., per-sentence targeted prompting), split into
  `cite_suggest_batch.py` and `cite_suggest_targeted.py`.
- **Source-id deduplication in cite_suggest** — when a source appears in both
  `sources:` and `synthesizes:`, it is currently loaded twice. Deduplicate
  before prompt assembly.
- **Network-level retry path test** — structurally identical to the
  `APIStatusError` retry branch but currently exercised only by the status-code
  tests. Add a dedicated `APIConnectionError` mock test.
- **Retry-loop dedup helper** — `_should_retry()` extraction for cleaner
  status-code + network-error retry in a single helper.
- **`LLMError` to dedicated module** — `api_client.py` imports `LLMError` via
  a deferred import to avoid a circular dep. Move `LLMError` to a thin
  `gateway.llm.errors` module.
