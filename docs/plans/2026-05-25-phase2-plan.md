#### AGT-9 — Filesystem event bus

**Reference:** § 8, AGT-9.
**Effort:** M
**Deps:** none

Agents today have no way to subscribe to gateway events without polling `log.md`. The event bus decouples emitters (ingest, filter, poll) from subscribers (triage agent, draft closer, digest).

**Files:**
- New: `src/gateway/events.py` — `emit(event_type, payload)`, `subscribe(agent_name, event_types)`
- New: `.knowledge/agents/<name>.yaml` — subscription YAML schema
- `.knowledge/events/<date>/<seq>.json` — event store (filesystem, append-only per day)

**Schema (event JSON):**
```json
{
  "event_id": "<uuid>",
  "event_type": "ingest.complete | filter.scored | poll.complete | ...",
  "correlation_id": "<log.md entry id>",
  "agent": "<emitting agent name>",
  "payload": {},
  "emitted_at": "<iso8601>"
}
```

**Subscription YAML schema:**
```yaml
agent: inbox-triage
subscribes_to: [ingest.complete, poll.complete]
debounce_s: 30
max_concurrent_runs: 1
```

**Acceptance:**
- `emit()` writes to `.knowledge/events/<date>/<seq>.json`. Seq is zero-padded, monotonic within day.
- `subscribe()` reads subscription YAML and returns matching event files since a cursor.
- Debounce window prevents multiple triggers within N seconds of each other.
- `max_concurrent_runs` enforced via lock file.
- Correlation-id matches corresponding `log.md` entry.
- Tests: emit writes file; subscribe returns matching events; debounce suppresses duplicates; max-concurrent-runs blocks second trigger.

**Pattern:** Look at `.knowledge/locks/` pattern in `locking.py`. Event store is similar — filesystem, no external deps.

#### AGT-1 — Inbox-triage agent

**Reference:** § 8, AGT-1.
**Effort:** M
**Deps:** AGT-9

Triggered by `ingest.complete` and `poll.complete` events. Dispatches newly ingested sources to domains; routes filter-band sources to a triage queue for human review.

**Files:**
- `src/gateway/agents/inbox_triage.py`
- `src/gateway/cli.py` — `triage list` subcommand
- `.knowledge/agents/inbox-triage.yaml` — subscription config

**Logic:**
1. On event: read source frontmatter.
2. If domain already set: run `wiki filter --domain <X>` and persist score.
3. If domain absent: attempt domain inference from title + tags against existing policies; if confident → tag and filter; if not → tag `needs-domain`.
4. If filter score in review band: add to triage queue at `.knowledge/triage/<source_id>.yaml`.
5. Never runs `wiki filter-correct` autonomously.

**Acceptance:**
- Triggers on `ingest.complete` and `poll.complete` events via AGT-9 subscription.
- `needs-domain` tag applied to sources where domain inference confidence is below threshold.
- Review-band sources appear in `wiki status` triage count.
- `wiki triage list` shows review-band sources with source ID, title, score, inferred domain.
- No autonomous `filter-correct` calls under any path.
- Tests: event triggers agent; domain-present path runs filter; domain-absent path tags `needs-domain`; review-band sources queued.
